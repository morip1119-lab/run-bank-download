================================================================================
Cloud Run に Google OAuth 用 client_secret.json / token.json を載せる手順
================================================================================

★ 推奨（2025）: ファイルマウントではなく「環境変数で Secret を参照」
  コードは GOOGLE_CLIENT_SECRET_JSON / GOOGLE_TOKEN_JSON に対応済み。
  コンソール: 変数とシークレット → 環境変数を追加 → 値のソースで Secret を選択。

  - 名前: GOOGLE_CLIENT_SECRET_JSON  → シークレット google-client-secret-json
  - 名前: GOOGLE_TOKEN_JSON         → シークレット google-token-json

  あわせて（手元の google-auth と同じなら）:
  - GOOGLE_OAUTH_REDIRECT_URI = http://127.0.0.1:8765/

  デプロイ後、LINE で「カレンダー登録する」を再テスト。

  ※ 以前の /secret-client/ などのボリュームマウントは不要なら削除してよい。

--------------------------------------------------------------------------------
以下は「ファイルとしてマウントする」古い手順（ディレクトリ制約あり）
--------------------------------------------------------------------------------

■ 前提
  - 手元の PC に、すでに動いていたときの client_secret.json と token.json がある
  - gcloud が使え、プロジェクトが chirashi-493513（または自分の ID）になっている

■ 1. プロジェクト番号を確認（IAM 用）

  gcloud projects describe chirashi-493513 --format="value(projectNumber)"

  表示された数字をメモ（例: 113972940274）

■ 2. Secret Manager にファイルを登録（初回）

  line-secretary-calendar フォルダで、実在するパスに合わせて実行:

  gcloud secrets create google-client-secret-json --data-file=client_secret.json --project=chirashi-493513

  gcloud secrets create google-token-json --data-file=token.json --project=chirashi-493513

  既に同名シークレットがある場合は「バージョン追加」:

  gcloud secrets versions add google-client-secret-json --data-file=client_secret.json --project=chirashi-493513

  gcloud secrets versions add google-token-json --data-file=token.json --project=chirashi-493513

■ 3. Cloud Run の実行サービスアカウントに参照権限を付与

  PROJECT_NUMBER を 1 で出た数字に置き換え:

  gcloud secrets add-iam-policy-binding google-client-secret-json ^
    --project=chirashi-493513 ^
    --member="serviceAccount:PROJECT_NUMBER-compute@developer.gserviceaccount.com" ^
    --role="roles/secretmanager.secretAccessor"

  gcloud secrets add-iam-policy-binding google-token-json ^
    --project=chirashi-493513 ^
    --member="serviceAccount:PROJECT_NUMBER-compute@developer.gserviceaccount.com" ^
    --role="roles/secretmanager.secretAccessor"

  ※ Cloud Run の「サービスアカウント」をコンソールで変えている場合は、そのメールアドレスに合わせる。

■ 4. Cloud Run にシークレットをファイルとしてマウントし、環境変数を指定

  ★ 同じディレクトリ（例: /secrets/）に2ファイルをマウントするとエラーになることがある。
    親フォルダを分ける（公式の制約に合わせた例）:

  gcloud run services update line-secretary-calendar ^
    --region=asia-northeast1 ^
    --project=chirashi-493513 ^
    --update-secrets="/secret-client/client_secret.json=google-client-secret-json:latest,/secret-token/token.json=google-token-json:latest" ^
    --update-env-vars="GOOGLE_CLIENT_SECRET_PATH=/secret-client/client_secret.json,GOOGLE_TOKEN_PATH=/secret-token/token.json,GOOGLE_OAUTH_REDIRECT_URI=http://127.0.0.1:8765/"

  ※ 既に LINE 用の環境変数があるときは --update-env-vars で追記される（消えない）。
    全部まとめて入れ直す場合はコンソールの「変数とシークレット」でも可。

  GOOGLE_OAUTH_REDIRECT_URI は、手元で npm run google-auth したときと同じ URI に合わせる（token 取得時と同じ）。

■ 5. 動作確認

  LINE で「カレンダー登録する」→ Google カレンダーに予定が入るか確認。

■ トラブル時
  - Permission denied on secret: 手順 3 のサービスアカウントが違う。Cloud Run の「セキュリティ」タブの SA を確認。
  - まだファイルが無い: コンソール → Secret Manager でシークレット名・バージョンを確認。
